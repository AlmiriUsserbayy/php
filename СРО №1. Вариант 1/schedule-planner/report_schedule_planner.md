## 1. Введение и цели проекта
Целью данной самостоятельной работы является закрепление практических навыков разработки серверных веб-приложений на чистом языке **PHP 8.4+** с использованием строгой типизации (`strict_types=1`). 

В рамках проекта «Планировщик учебного расписания» решены следующие задачи:
* Проектирование многомерной структуры данных для представления расписания занятий.
* Реализация механизмов фильтрации данных по нескольким критериям одновременно.
* Обеспечение контролируемой сортировки коллекций по временному признаку.
* Создание механизма сохранения пользовательского состояния (избранных предметов) на стороне сервера с помощью сессий (`$_SESSION`).
* Автоматическое выявление наложений и конфликтов в расписании (усложненное задание).
* Реализация динамической выгрузки отфильтрованных данных в формате JSON (усложненное задание).

## 4. Описание программной реализации

### 4.1. База данных (`var/data/schedule.json`)
Хранилище содержит массив объектов, каждый из которых обладает уникальным идентификатором, днем недели, временем начала, названием дисциплины, кодом академической группы, ФИО преподавателя и типом занятия (Лекция/Практика/Лабораторная).

### 4.2. Модуль бизнес-логики (`src/functions.php`)
Включает функции, работающие в режиме строгой типизации:
1. `loadSchedule(string $filePath): array` — выполняет безопасное чтение и декодирование JSON-файла с проверкой его целостности.
2. `filterSchedule(array $schedule, string $day, string $group, string $teacher, string $type): array` — фильтрует массив с помощью `array_filter()`, поддерживая частичное совпадение по подстроке ФИО преподавателя без учета регистра.
3. `sortSchedule(array $schedule): array` — сортирует список занятий в хронологическом порядке через `usort()` и алгоритм `strcmp()`.
4. `checkConflicts(array $schedule): array` — выполняет парный перебор элементов для обнаружения ситуации, когда для одной и той же группы или одного преподавателя назначено два разных предмета на одно и то же время.

### 4.3. Контроллер и представление (`public/index.php`)
Маршрутизатор обрабатывает входящие HTTP-запросы:
* **GET-запросы** используются для чтения и применения кастомных фильтров отображения.
* **POST-запросы** обрабатывают добавление элементов в сессионное избранное, защищая сценарий от дублирования операций при обновлении страницы по паттерну PRG (Post-Redirect-Get).

## 5. Валидация, безопасность и отказоустойчивость
* **Защита от XSS-атак:** Любой вывод пользовательских или внешних данных из JSON экранируется с помощью функции `htmlspecialchars()`, предотвращая внедрение вредоносных скриптов в структуру DOM.
* **Контроль состояния:** Сессионные файлы хранятся исключительно на сервере. В браузер клиента передается только зашифрованный куки-идентификатор сессии.
* **Устойчивость к сбоям:** При отсутствии файла `schedule.json` или его повреждении, функция `loadSchedule` перехватывает ошибку и возвращает пустой массив, предотвращая аварийную остановку сервера (Fatal Error) и сохраняя работоспособность интерфейса для пользователя.
